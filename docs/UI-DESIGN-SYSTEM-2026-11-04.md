# FOSS-Atlas 统一 UI 系统 — 2026-11-04

## 目标

导航、知识图谱、自部署服务和 Wiki 是同一款产品的四种工作视图，不应像四个各自拼装的页面。统一的是品牌、排版、内容边界、表面层级、控件尺寸和响应式规则；保留每个页面真正需要的结构差异：资源发现用卡片网格，关系探索把画布放在中心，部署页使用服务列表，Wiki 保留三栏知识阅读。

本轮先建立了深色主题下的共享组件；随后首页体验复审发现，仅统一组件仍保留了后台面板式的信息堆叠，因此首页结构在同日追加重整为搜索优先目录，并将全站表面调整为更清爽的浅色层级。不引入新的 UI 运行时依赖。

## 参考项目与取舍

- **shadcn/ui**（shadcn-ui/ui）：采用可组合、语义化的设计系统思路。借鉴先定义颜色角色、字体、间距、圆角和 elevation，再规范基础组件与组合组件的顺序；不直接复制其默认皮肤。项目：https://github.com/shadcn-ui/ui；Sidebar 组件规范：https://ui.shadcn.com/docs/components/base/sidebar
- **Plane**（makeplane/plane）：成熟的工作台式产品，页面标题、工作区视图、过滤器和内容区域层次明确。借鉴页面主标题与工作控件分层，以及列表和画布等视图共享外壳的做法。项目：https://github.com/makeplane/plane
- **Twenty**（twentyhq/twenty）：复杂记录型应用，导航、视图和详情页需要保持稳定一致。借鉴详情页标题、元数据、主要操作分组，以及宽屏信息布局的秩序。项目：https://github.com/twentyhq/twenty
- **coss.com/ui**（Cal.com 官方设计系统）：以 Base UI primitives 与 Tailwind 组成可组合组件。借鉴控件语义、状态和尺寸统一，不增加另一套组件库。项目：https://github.com/cosscom/ui

高 Star 数只作为项目发现和筛选线索，不当作设计质量分数，也不意味着照搬它们的视觉风格。

| 项目 | 规则 |

| 页面左右留白 | clamp(18px, 1.6vw, 36px)，随屏幕宽度缓慢增长 |
| 页面主区块间距 | clamp(24px, 2vw, 32px) |

| 区块标题 | 15px / 1.35 |
| 常用控件高度 | 34px，6px 圆角 |
| 面板圆角 | 继续使用 8px 主题圆角 |
| 表面层级 | 页面底色、主要内容面板、次级或画布面板三级 |

### 共同组件

- PageHeader：页面眉题、标题、描述、操作区、可选摘要栏。首页摘要指标可放在 aside，其他页面不必为了对称而塞入假指标。
- SectionHeading：统一区块标题、数量、说明与可选操作。
- fa-surface / fa-surface-muted：分别表示主要内容面板和次级面板。
- fa-control：统一链接按钮、筛选和切换控件的边框、圆角、最小高度、hover 与 active 状态。
- fa-stat-tile：统计与可点击统计卡片共享尺寸；状态语义仍由现有 accent / own 颜色表达。

不再在各页面任意选择 20px、24px、32px 的标题字号，也不为相似面板重新写一套底色、边框和圆角。

## 视觉层级复核（第二轮）

统一外壳之后，还要保证每个页面的主任务足够突出：

- **导航页**：搜索是首要入口；分类和费用筛选默认收起，已部署与收藏作为快捷视图。资源卡片成为首要内容，桌面和手机分批显示，继续浏览由用户主动加载。
- **知识图谱**：画布是页面主体。聚焦分类、部署范围和关系过滤默认收起，桌面与移动端使用同一个明确的筛选入口；筛选状态仍保留在 URL 中。操作说明按需展开，工具栏只提示最主要的节点、平移和缩放动作。
- **Wiki**：1280px 以上使用正文 + 元数据双栏，目录作为独立导航轨；768–1279px 优先给正文留宽度，元数据放到正文之后，不再让三列同时挤压阅读区域。
- **全站背景**：移除重复点阵纹理，保留低强度环境光晕，避免卡片、标签和页面背景同时争抢注意力。

## 四种页面的布局职责

1. **导航页**：使用独立的搜索优先结构；主标题和搜索是首屏的两个主元素，收藏/已部署是快捷视图，分类与费用类型默认收起到筛选面板；资源卡片是主内容，不再让统计 tile 和常驻标签墙抢占首屏。
2. **知识图谱**：标题区与其它页同级；画布是主视觉，图例、筛选和节点列表是辅助面板；不把图谱强行压进普通卡片网格。
3. **自部署服务**：以查找为首要任务，支持名称、域名、技术栈与分类检索，按发布快照状态和部署位置筛选；分组三态摘要默认收起实例列表，搜索结果自动展开匹配分组；探测明细和长篇运维笔记按需展开。
4. **Wiki**：共享同一标题样式和操作控件；桌面保留“目录导航 + 正文 + 元数据”的阅读工作区，左侧目录变为内容边界内的导航面板；右侧优先呈现分类、子类等核心元数据，标签、实例、替代项和反向链接收进渐进展开区；手机仍用目录抽屉，右侧元数据自然下沉。

## 响应式与可访问性

- 1440px 桌面、1024px 窄桌面、390px 手机和 320px 极窄手机都必须无横向页面溢出。
- 首页桌面默认先展示 24 项、手机默认 8 项，并提供“加载更多”；完整目录仍可通过搜索与筛选访问，不以一次性渲染所有卡片换取信息完整。
- 大屏工作区不设置固定居中窄容器：导航栏、全宽页面和 Wiki 工作区都跟随浏览器宽度；首页资源网格从 1440px 起逐步扩展为 4 / 5 / 6 / 7 列（1440 / 1920 / 2560 / 3200px），而不是把三张卡片撑到很宽。
- 知识图谱画布在超宽显示器上可使用最多 80vh / 1280px 的高度，右侧图例工作区在 2xl 屏幕扩至 320px；自部署实例列表在 2xl 屏幕扩为三列。
- Wiki 外层目录与阅读工作区铺满可用宽度，但 Markdown 正文继续限制在约 78ch，元数据与目录作为独立辅助栏，不随视口无限拉宽正文。
- Wiki 桌面目录树在断点以下隐藏，手机用目录抽屉；不能让桌面侧栏在移动端占位。
- 状态切换继续使用 aria-pressed / aria-expanded；键盘焦点可见；减少动态效果时响应 prefers-reduced-motion。
- 长 URL、仓库路径和命令不能把小屏撑宽；运维说明使用 anywhere 换行，而不是强制整段横向滚动。
- 不以装饰插画、渐变发光或 emoji 堆叠来美化页面；重点是信息层级、间距、状态和一致的交互反馈。

## 防漂移约定

新增一级页面必须使用 PageHeader，区块使用 SectionHeading，可交互面板优先使用 fa-surface / fa-control。若页面有真实结构需要例外，应记录原因，不应自行创造第二套标题、卡片和控件样式。


## 首页交互重整补充（2026-11-04）

- 搜索与 URL 查询参数双向同步，按斜杠键聚焦搜索；名称、描述、标签、域名与明确标注的免费方案均可检索。
- 分类、子分类、免费方案与只看已部署沿用原 URL 参数；筛选面板默认关闭，条件变化后结果数量和条件标签同步变化。
- 收藏保存在浏览器本地；资源卡片提供收藏星标、比较入口、Wiki 详情和官网直达；列表与卡片视图偏好也会保留。
- 资源比较最多三项，底部托盘随选择出现，比较面板展示分类、免费方案、自部署状态与官网入口。
- 桌面以三列卡片呈现，窄屏改为单列；首屏分页数量为桌面 24 项、手机 8 项，并尊重减少动态效果设置。

## 跨页面信息密度复审补充（2026-11-04）

- 图谱页保留画布、图例与筛选能力；长操作指南不再常驻侧栏。标题说明改为任务描述，不重复堆叠全部统计数字。
- 自部署页新增跨名称、域名、技术栈、分类和标签的查找；状态筛选区分不可达、受限、正常响应、普通重定向和未探测。3xx 不能自动当作健康，登录重定向归入受限。
- 自部署页分组摘要默认折叠详细实例，筛选后自动展开命中组；现有 `/deployed/#<id>` 深链接会先展开所在分组再定位实例。探测快照和运维细节不丢弃，只改为渐进披露。
- Wiki 右侧保留核心元数据与图谱入口；次级关联信息归并进“更多信息与关联”，减少无关面板对正文的持续挤压。
- 发布探测仍明确标注为快照而非实时监控；所有过滤条件均按快照分类，不把 HTTP 可达等同于登录或完整用户流程可用。

## 图谱局部关系模式（2026-11-04）

- 参考 Obsidian Graph View 的 Local Graph：从节点速览进入，以该节点为中心查看邻近关系，而不是再设计一套独立的图谱页面。
- 局部图入口同时放在画布节点速览和列表行操作中；两种浏览方式使用同一 URL 状态与返回路径，不把局部关系功能锁在鼠标画布上。
- 深度只提供 1 跳 / 2 跳；超过两跳会迅速回到全局密集图，不作为默认交互。
- 沿用现有关系过滤。关闭某种关系时，该关系不参与局部节点扩展；当前锚点始终保留。
- 局部节点与深度写入 URL，可分享和刷新恢复；显式退出返回全图。切换分类聚焦或已部署视图时自动退出局部模式，避免互相矛盾的筛选同时生效。
- 原有 ECharts 冻结布局、节点拖动、缩放和聚焦规则不另起炉灶，局部模式复用现有节点位置和焦点高亮。

## 阅读与目录视图模式（2026-11-04）

- **Wiki 阅读**借鉴 Outline 的章节导航与连续阅读：桌面右侧目录随当前章节高亮，窄屏改为正文内可折叠目录；目录链接使用真实 heading 锚点。阅读进度是轻量进度线，不引入新的阅读状态面板。
- Wiki 页间导航只在当前细分领域内提供上一篇 / 下一篇，避免从一篇内容突然跳到无关分类；原有左侧工具目录仍负责跨工具切换。
- **导航目录**借鉴 Backstage / Plane 的 URL-backed filters 与视图：搜索、分类、免费方案、已部署 / 收藏快捷视图、排序、卡片 / 列表模式均能从地址栏恢复。收藏数据仍只在本地，`saved=1` 表示按当前浏览器的个人收藏过滤，不会把收藏列表上传或伪装成跨用户共享数据。
- **自部署服务**的搜索、连通性状态与部署位置筛选写入 URL；复制地址可以恢复同一组筛选。分组展开状态仍属于临时阅读状态，不会污染分享链接。
- 清除筛选只清除过滤条件，保留用户选择的排序与视图；未知查询参数也会保留，避免覆盖外部分享追踪参数。

## 微交互与探索入口（2026-11-04）

- 全站命令面板参考 Obsidian Quick Switcher / Raycast：空查询先显示快速操作，再显示最近阅读；搜索支持多词同时匹配；方向键选择、Enter 打开、Tab 焦点循环、Escape 关闭并恢复打开前焦点。
- 最近阅读仅保存在当前浏览器 `localStorage`，最多六条有效 Wiki 资源 ID；不上传、不跨设备同步，也不改变公开目录数据。
- 首页“随便逛逛”和命令面板“随机探索”都优先避开已收藏或最近访问的条目；探索入口保持轻量，不插入首页卡片流。
- Wiki 围栏代码块提供一键复制与短暂成功 / 失败反馈；保留原始 Markdown 与横向滚动，不自动执行代码。
- 收藏星标、命令面板出现与代码复制均有短促反馈；`prefers-reduced-motion` 下关闭新增动画，触摸设备上复制按钮保持可见。

## 资源比较弹窗的键盘行为（2026-11-04）

- 资源比较弹窗打开时，焦点移入弹窗；`Tab` / `Shift+Tab` 在弹窗内循环，若焦点被脚本意外移出，下次按键会拉回弹窗边界。
- 点击“比较所选”时同步将目录主体设为 `inert` + `aria-hidden` 并锁定页面滚动，避免打开弹窗与 React effect 之间出现背景可操作的时间窗；底部比较托盘位于 inert 区域之外，使触发按钮仍是有效的焦点归还目标。
- 关闭或按 `Escape` 后同步恢复原滚动设置、移除背景隔离属性，并立即把焦点归还到原触发按钮（不延迟到下一帧）。
- 焦点循环只纳入当前可见、可聚焦的链接和按钮；正向从最后一项回到关闭按钮，反向从关闭按钮回到最后一项。

## 阅读导航的焦点连续性（2026-11-04）

- Wiki 目录链接不仅滚动到章节，也应把程序焦点移动到对应的 `h2` / `h3`，避免键盘和读屏用户视觉位置已变、阅读焦点却留在目录中的断层。
- Markdown 标题保留原有稳定 slug，并设置 `tabIndex=-1` 作为可编程焦点目标；它不进入普通 Tab 顺序，不增加额外键盘停靠点。
- 标题继续使用统一 `scroll-margin-top`，深链接、桌面目录和窄屏目录共用同一锚点规则。

## 跨页面滚动与浏览历史（2026-11-04）

- 路由外壳统一管理滚动，不让 Wiki 页面与全局导航各自抢着滚到顶部；浏览器原生 `history.scrollRestoration` 设为 `manual`，避免和应用恢复逻辑竞争。
- 进入新页面（`PUSH`）从顶部开始；同一路径内搜索、筛选、视图等 URL 状态变化保持当前阅读位置。
- 浏览器后退 / 前进（`POP`）按 React Router 的 history key 恢复对应条目的滚动位置，最多保留最近 100 个条目，页面刷新后不持久化。
- 显式 hash 深链接优先于历史滚动位置。自部署实例链接仍先展开所属分组，再滚动到实例行；Wiki 章节锚点继续使用标题的 `scroll-margin-top`。
